# Статистический арбитраж на MOEX

Python 3.12+ проект для исследования коинтегрированных пар, причинного бэктеста рублёвых фьючерсов и локального paper/replay.

## Установка

```bash
uv sync
```

## Финансовый бэктест

Подготовьте два набора OHLCV, **исторические спецификации контрактов**, капитал, бюджет пары и явные издержки. Пример структуры конфигурации и формата спецификаций — в [инструкции](docs/superpowers/runbooks/causal-backtest.md).

```bash
uv run python -m statarb.research.cli --config research.json --output results/run-001.json --journal results/run-001.jsonl
```

Модель обучается только на прошлых данных. Сигнал после закрытия бара исполняется на следующем общем `open`. Количества — целые контракты; хедж и коэффициенты фиксируются при входе. Комиссии и ухудшение цены учитываются для каждой ноги при входе и выходе. Equity и обеспечение рассчитываются общим с paper движком.

В `data/` есть часовые CSV десяти фьючерсов 2025 года. Они подходят для исследования цен, но **не содержат исторического ГО и стоимости шага**: без дополнительных спецификаций финансовый запуск завершится диагностикой. Тарифы и исторические параметры не подставляются автоматически.

Python API: `BacktestRequest`, `BacktestResult`, `run_backtest`, `run_universe` из `statarb.research`. Старые `core.Backtester` и `ImprovedBacktester` принимают `request=...` и используют тот же движок. Расчёт финансовой доходности только по двум массивам закрытий и неоднозначные старые комиссии больше не поддерживаются.

Результат сохраняет модели, решения, события исполнения, equity, издержки и допущения с хешами входов. Открытые остатки оцениваются по последним ценам; стоимость предполагаемой ликвидации показывается отдельно. Прогоны нескольких пар используют независимые счета и не являются общим портфелем.

## Paper/replay и данные Alor

```bash
uv run python -m statarb.runtime.paper_trading_day --journal-path /tmp/paper-day-new.jsonl
```

Это smoke контрактов на исторических ценах с **явно синтетическими параметрами инструментов**. Он использует конечное состояние стратегии, включая flat, и не подтверждает доходность. Полный финансовый цикл и replay проверяются отдельно в тестах.

Для загрузки/поиска нормализованных данных используйте `python -m statarb.data.alor_fetch --help`. Paper smoke поверх внешних Alor датасетов требует `--specifications`, `--pair-budget`, `--max-hedge-error` и фактический `--timeframe`. [Runbook paper/replay](docs/superpowers/runbooks/paper-trading-day.md).

## Проверка

```bash
uv run pytest -q
uv run ruff check core statarb tests
```

Тесты не подключаются к брокеру. Проверяются причинность, временное выравнивание, ручные расчёты PnL, целочисленный хедж, отказы записи, восстановление, повторные fills и подмена промежуточных снимков replay.

## Структура

- `statarb/research/` — оценка моделей, состояние пары, sizing, бэктест и отчёты.
- `statarb/data/` — проверка баров, Alor datasets и reference data.
- `statarb/domain/` — контракты инструментов, спецификаций и финансовых событий.
- `statarb/runtime/` — paper, журнал транзакций, replay и read models.
- `core/` — совместимые входы старого исследовательского API.
- `tests/` — проверки расчётов, контрактов и интеграций.
- `notebooks/` — прежние исследовательские эксперименты; старые финансовые результаты требуют пересчёта.
- `docs/` — [контракты и архитектура](docs/README.md), включая [ADR 0005](docs/adr/0005-causal-futures-research-and-shared-paper-ledger.md).

Текущая модель не включает брокерские команды, ролловер, доставку, денежные расчёты по расписанию клиринга и очередь исполнения.
